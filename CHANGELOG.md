# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.2.0] - 2026-09-17

### Added

- `fmsave.open()` and the `Save` object, used as a context manager, with `Save.info`: game, build, database version and in-game date.
- Readers for players, contracts, suspensions, clubs, managed clubs, stages, competitions, fixtures, transfer windows, league tables, competition rules and per-match player stats: `Save.players()`, `Save.contracts()`, `Save.suspensions()`, `Save.clubs()`, `Save.managed_clubs()`, `Save.stages()`, `Save.competitions()`, `Save.fixtures()`, `Save.transfer_windows()`, `Save.league_tables()`, `Save.competition_rules()` and `Save.player_match_stats()`.
- The fixture calendar: `Save.fixtures()` returns every match the save has scheduled or played, in date and kick-off order, joined to its competition through its stage and to a club through each team id, with the kick-off time, the round, the season and whether the match was played away from the home club's usual ground. A save holds several copies of its calendar, one of them a block of template matches dated years off the clock that belong to no career; only the career's own calendar is returned, and the reader counts what it left behind. `export` writes the table under any scope: a club, managed-club or nation scope keeps a match either side of which is in it.
- Match scores on the fixture rows: `home_goals` and `away_goals` are filled in from the separate stage-keyed records the save stores scores in, joined to a match by its date and both team ids. Retention is partial by design, covering about a quarter of the matches a career has played, so a played match with empty goals means the save no longer holds that score rather than that it finished goalless. A record naming no match in the calendar, or naming two at once, fills nothing, and two records disagreeing about one match leave it unscored.
- Transfer windows: `Save.transfer_windows()` returns every transfer window the save's rules database holds, in stored order, with the day and month each one opens and closes and which of the season's two years each date falls in. A window is database content rather than career state, so every save made from one installed database carries the same windows; the dates are season-relative rather than calendar dates, and a window carries no name of its own. The rules database stores more window records than it has distinct windows, and rows that repeat are equal in every field, so deduplicate if you want one row per window. `export` writes the table under `--all`, the only scope it takes: a window names no club, competition or nation fmsave can read.
- Live league tables: `Save.league_tables()` returns every table the save holds, in the order the save stores them, with one row per club carrying its total record, its home, away, first-half and second-half splits, and one slot per match with the opponent, the score, the result and the points. One table is one run of blocks, told from the next by the index each block keeps of its own place in its table; the save stores each block several times over, so repeated content is dropped before the tables are built. Rows keep the save's own standings order, which is the league position, and must not be re-sorted: the game separates clubs level on points by their results against each other first, and no field here carries that. Nothing in a table names its competition, so it is voted for from the fixture calendar, and a table the vote cannot settle carries none and is still returned; the vote settles almost every table, though 30% to 43% of tables hold a single club and settle on a majority of one, and over the tables of two clubs or more it settles 0.998 to 1.000 of them. Whether a slot was played at home or away is not shipped: the save alternates venue with the slot's parity but never says which parity is home, and the evidence is not strong enough to name it, so `venue` is empty on every slot. `export` writes the table under any scope, always whole tables: a club or nation scope keeps the standings a club of it sits in.
- Competition rules: `Save.competition_rules()` returns every rules block the save holds, in stored order, with a competition's promotion, play-off and relegation places, its tie-break codes, its prize money by finishing position and its round calendar. No row names the competition it belongs to, because the save stores no link and a measured search for one found none, so `competition_id` and `competition_name` are empty throughout and a division is matched by `fixtures_per_club` against `league_tables()`. Every field is unconfirmed, since no row can be tied to a competition to check it against the game. `export` writes the table under `--competition` or `--all`, and since no row names a competition, `--competition` returns no rows.
- Per-match player stats: `Save.player_match_stats()` returns a table of `PlayerMatchStats` rows, one for every match a player played that the save still holds a record of, in player order and, inside each player, in the order the save stores them. Each row carries the date, the competition id in the stage id space, the opponent's first-team id and the club fielding it, and, where the save kept a performance body, the position played, minutes, goals, assists, the rating, the minute the player left the pitch and both pass counts. The save keeps only about twenty matches per player per spell at a team, across all competitions at once, so this is never a whole season and a per-competition total summed from these rows is truncated without saying so; friendlies, internationals and youth matches are kept apart from these records and are not here at all. A match the save kept no body for carries its date, competition and opponent and nothing else, because the record stops there. The position is a bit mask belonging to this table alone, read as a `MatchPosition` coded value: only the goalkeeper bit is named, and every other mask ships as a raw number rather than being given a meaning the game never displayed. `body_valid` reports whether fmsave finds a body's own numbers sound, and a body it does not is flagged and kept exactly as stored. `export` writes the table under any scope, keeping the matches of the players a club or nation scope holds.
- Stage and competition rows: a stage is one part of a competition, such as a league season, a cup round or one leg of a two-legged tie, and its id is what fixtures, league tables and per-match records join through. `Save.competitions()` lists every competition the stage table names with the ids of its stages. The save stores no competition names, so those rows carry none until a name map is supplied, and `export` writes both tables under `--competition` or `--all`.
- Competition names from a map you supply: `fmsave.open(path, competition_names=...)` takes either a mapping of editor database id to name or the path of a two-column CSV, and `fmsave.read_competition_names()` reads such a file on its own. The key is the editor database id because that value is the same in every save and is what name sources outside a save are keyed on. A name fills `Competition.name` and every denormalised `competition_name`. fmsave ships no names, reads no game install and makes no network call.
- `Table`, an immutable sequence of records with `where`, `filter`, `find`, `by_uid`, `get_by_uid` and `coverage`, and export through `to_dicts`, `to_columns`, `to_pandas`, `to_polars`, `write_csv`, `write_json` and `write_jsonl`.
- A stable flat output schema, versioned as `fmsave.OUTPUT_SCHEMA_VERSION`.
- `fmsave.field_status`, which tells whether a field's meaning is verified or unconfirmed.
- Reader checks that reject a save whose layout does not match, and `fmsave.validate_save`, a report of checks, counts and coverage with no names or uids.
- The `fmsave info`, `fmsave export` and `fmsave validate` commands. `export` requires a scope, and writes every table a reader returns; each table takes only the scopes its rows can answer and says which those are when it turns one down. `--competition` takes a competition id, or a name once `--competition-names` has supplied one for the run.
- Affiliate teams: a player registered with a team another club controls, such as a B team the save stores as a club of its own, is a player of the controlling club, keeps the club storing his team in `team_club_uid`, and is not on loan. A club's `teams` list the teams it controls after its own slots, and an affiliate club's row carries its `parent_club_uid`.
- `Player.contract` and `contracts()` rows are the contract in effect at the save's in-game date, taken whole from one chain record; agreed future moves such as pre-contracts stay in the chain but never fill it. `on_loan` marks a real loan, with the club of that contract as the parent club and the loan's own dates in `loan_start` and `loan_end`. For a player away from the club that pays him, the parent club is the club of his oldest running record that carries something of a contract, so an offer from another club is never mistaken for it, whether it was made after that record or days before it.
- Optional `pandas` and `polars` extras.

### Changed

- `fmsave validate` runs and reports all twelve readers, and a reader that fails its checks is reported beside the eleven others rather than stopping the report.
- `fmsave export` takes a table name for every reader, and a table it will not write under a given scope names the scopes it does take.
- Squad status reads as a label rather than a raw number for every code a save actually uses: the game offers one set of statuses for goalkeepers and another for everyone else, and the two sets do not share every code. Two codes carry the same words, "Emergency Backup", one from each list, so the code still says which list the status came from. A contract's release clause now also distinguishes a release to domestic clubs in a higher division from a plain domestic one.

### Fixed

- Nothing: this is the first documented release, so there is no earlier behaviour to correct.

### Notes

- `fmsave.OUTPUT_SCHEMA_VERSION` stays 1: this release adds record types and columns, and renames or removes none.
- Competition names are not read from any save, and none are shipped. A competition carries its editor database id, and a name only where the map you supply has one.
- A fixture, a league table and a rules block carry an empty competition rather than a guessed one wherever the save stores no link fmsave can follow.
